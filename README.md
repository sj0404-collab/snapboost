# SnapBoost

Тюнер телефона для игр на Snapdragon. Приложение **настраивает** то, что Android
позволяет настроить обычному приложению: маршрут звука, помехи, обработку
микрофона, яркость, фоновые процессы. Плюс — оверлей с реальными метриками
(частоты, температуры, троттлинг, PSI, нагрузка GPU), который включается
отдельной кнопкой.

Главный сюжет — звук в играх вроде Genshin Impact. Жалоба одна: звук «рычит»,
рвётся, не вывозит спецэффекты. Причина почти всегда одна — **аудиобуфер не
успевает наполняться**: игровой `AudioTrack` отдаёт данные с задержкой, буфер
опустошается, HAL не успевает его перезаполнить, и в выходе появляются щелчки.

Приложение ничего не «разгоняет». Оно измеряет, что мешает смартфону, и
применяет те меры, которые Android разрешает применять легально.

---

## Главное ограничение: только публичный API

Ни root, ни Shizuku, ни `adb`, ни внешних сервисов. Приложение работает от
своего UID и не просит ничего, кроме обычных разрешений.

Следствие — и оно вынесено в интерфейс, а не спрятано: всё, что закрыто
системными правами, остаётся недоступным и показывается как `N/A`.

| Что | Статус |
|---|---|
| Частоты CPU, governor, троттлинг | читается из `cpufreq` |
| GPU: занятость, частота, троттлинг | читается из KGSL (Adreno) |
| Температуры, тепловой статус, headroom | читается из `thermal_zone` |
| Давление ресурсов (фризы) | `/proc/pressure/*` (PSI) |
| Частота вывода и размер буфера | `AudioManager.getProperty()` |
| Физический маршрут вывода | `AudioManager.getDevices()` |
| Частота дисплея | `Choreographer` |
| Настройки яркости, DND, Bluetooth, память | публичный API, применяется |
| Реальный FPS, jank, счётчик audio underrun | **N/A** — требуется `android.permission.DUMP` |
| Глобальные анимации, системный DSP, игровой режим | **N/A** — требуется `WRITE_SECURE_SETTINGS` |

`N/A` в приложении — это не баг и не «данные ещё не подгрузились». Это
указание на то, что источник закрыт. Подставной FPS опаснее отсутствующего:
по нему принимают решения о настройке железа.

## Профили в один тап

| Профиль | Что делает |
|---|---|
| **Чистый звук** | выключает Bluetooth, приглушает уведомления, освобождает фон, гоняет самотест аудиобуфера |
| **Тихая игра** | то же плюс обработка микрофона, тихий экран, защита от выгрузки в фоне |
| **Экономия энергии** | ручная яркость 25%, приглушенные уведомления, освобождение фона и кэша |
| **Сбросить** | возвращает яркость, автояркость, уведомления и микрофон в исходное состояние |

Каждый шаг отчёта подтверждается чтением значения обратно из системы. Три
исхода, и все три показываются честно:

- **применено** — система приняла изменение, это подтверждено чтением;
- **нужно подтверждение** — система открыла свой диалог (выключение Bluetooth
  на Android 13+, запрос на игнорирование оптимизации батареи);
- **не вышло** — Android запретил операцию, приложение говорит об этом прямо.

Яркость запоминается до первого понижения, поэтому «Сбросить» возвращает то
значение, которое человек выставил руками, а не 100%.

## Ручные переключатели

- **Маршрут вывода** — состояние Bluetooth и A2DP, кнопка выключения, переход
  в настройки звука. Маршрут вывода чужой игры обычному приложению неподвластен:
  единственный честный способ убрать A2DP из тракта — выключить Bluetooth.
- **Помехи** — «Не беспокоить», освобождение фоновых процессов, самотест
  аудиобуфера.
- **Микрофон** — шумоподавление, эхоподавление, автоусиление. Публичный API
  даёт доступ к эффектам только своей аудиосессии: если голосовой чат не
  запущен, приложение так и напишет, а не покажет зелёный переключатель.
- **Нагрев и ресурсы** — яркость и автояркость, состояние экономии заряда,
  занятость памяти, запрос не выгружать сервис в фоне, очистка своего кэша.

Состояние тумблеров читается из системы, а не из памяти приложения: если
яркость поменять в шторке, переключатель встанет в реальное положение сам.

## Самотест аудиобуфера

Единственная честная замена счётчику underrun из `media.audio_flinger`.
Создаёт `AudioTrack` с минимальным буфером — тем же, что выбирает игра — и
наблюдает через `getTimestamp`, успевает ли HAL его наполнять. Если число
записанных кадров перестаёт опережать число выведенных, буфер голодает, и
именно это слышно как щелчки.

## Оверлей с метриками

Отдельная кнопка в разделе «Оверлей с метриками», по умолчанию **выключен**:
приложение начинает с тюнера, а измерения включаются осознанно.

- **Короткое нажатие** — переключение режимов: полный → минимальный → выключен
- **Перетаскивание** — перемещение по экрану
- **Долгое нажатие** — открыть приложение

Показываются реальные частоты CPU и GPU, троттлинг, температуры, headroom, PSI,
загрузка процесса игры, маршрут и параметры аудиотракта. FPS, jank и счётчик
underrun — `N/A` по причинам выше.

## Установка

1. Скачайте `snapboost-release.apk` из релизов.
2. Разрешите установку из неизвестных источников.
3. `adb install -r snapboost-release.apk`
4. Выдайте доступ «Не беспокоить» — без него помехи не приглушаются.
5. Если нужен оверлей: «Отображение поверх других приложений».

## Осознанные ограничения

В приложении **нет** и не планируется:

- снятия тепловых лимитов (thermal governor) — это не буст, а ускоренный
  износ SoC; Snapdragon от такого теряет производительность навсегда
- записи в `cpufreq` и KGSL — нужно root, ломает гарантию и ухудшает
  стабильность
- модификации памяти игр, инжекта нативных библиотек, эмуляции ввода,
  обхода античита — это читы: нарушение условий игры и угроза бану аккаунта
- «мгновенного +40 FPS». Такого не существует: производительность упирается в
  нагрев и расчёт GPU, а не в настройки

## Сборка из исходников

```bash
./gradlew assembleRelease
```

APK попадёт в `app/build/outputs/apk/release/`.

Релизная сборка подписана ключом из репозитория
(`keystore/release.jks`, store/key password: `snapboost`). Он лежит в репозитории
намеренно, чтобы любой мог собрать APK из исходников. Для собственного
распространения замените его своим ключом в `app/build.gradle.kts`.

Тесты: `./gradlew test` — проверяются инварианты диагностики (пустые данные не
превращаются в ложные заключения) и логика профилей (шаги существуют, не
повторяются, отчёт не выдаёт ручной шаг за успешный).
